Executing on a remote machine: using musl-gcc

Up to this point, we have successfully executed exploit on qemu. The environment distributed this time is configured to allow network connection, so if you want to run it remotely, you can transfer the exploit using the wget command on qemu.
However, in some small environments such as CTF, the network is not available. In such cases, you will need to transfer the binaries remotely using the commands available in busybox. Base64 is generally used, but files built with GCC can range from several hundred KB to several tens of MB, so it takes a very long time to transfer. The reason for the large size is that the functions of the external library (libc) are statically linked.
If you want to reduce the size with GCC, you need to avoid using libc and define read, write, etc. yourself using system calls (inline assembly). Of course this is very difficult.
Therefore, many CTFers use a C compiler called musl-gcc for the purpose of kernel exploitation. Please download from the link below, build it and complete the installation.

https://www.musl-libc.org/

Once the installation is complete, do the following:transfer.shLet's rewrite the compilation part. Please specify the directory where you installed musl-gcc.

In the author's environment, the Hello, World program mentioned earlier was 851KB for gcc and 18KB for musl-gcc. If you want to make it even smaller, you can remove debug symbols using strip, etc.

Some header files (Linux kernel type) are not in musl-gcc, so you need to set the include path or compile with gcc. In such cases, if you build it via assembly once, you can use gcc functions and reduce the file size.
$ gcc -S sample.c -o sample.S
$ musl-gcc sample.S -o sample.elf
