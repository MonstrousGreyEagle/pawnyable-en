Double Fetch

Double Fetchis the name given to a type of data race that occurs in kernel space. As the name suggests, it refers to a conflict that occurs when the same data is fetched (read) twice on the kernel side.
When kernel space reads the same data from user space twice, another thread may rewrite the data in between, like this:

At this time, the data content differs between the first and second fetches, resulting in inconsistency. This kind of data race is called a double fetch.Conflicts dealt with in LK01The big difference is that this bug cannot be resolved by removing the mutex on the kernel side.

In this driver,verify_request and copy_data_to_user/copy_data_from_user is fetching the request data from the user. In other words,verify_request So pass the correct size and from there copy_data_to_user or copy_data_from_user If you rewrite the size to an invalid value before the is executed, a Heap Buffer Overflow can occur.

When handling user space data multiple times, you have to use the data that was copied to the kernel space first.
